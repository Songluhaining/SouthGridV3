# v6 评测：右腕相机视角在训练机与采集机(4060ti)不一致

> 结论先行：v6 模型在**训练机(RTX 4090)**上评测时，**右腕相机(camera_right)看不到按钮面板**
> （对着草地和自身手臂），导致黄/蓝按钮够不到。这**不是模型问题**——右腕相机这路输入在本机是坏的。
> 同一套模型 pak、同一 ready 关节位姿、同一相机 rotate 值，在 4060ti 上能看到面板，在本机看不到，
> 说明**两台机器的机器人/相机资产配置不一致**。本文说明现象、原因，并列出需要 4060ti 提供的对比信息。

## 1. 现象

评测拆两路相机：头相机 `camera_head`(端口 7090) + 右腕相机 `camera_right`(端口 7080)。

- **头相机正常**：能看到整块面板和按钮。
- **右腕相机在本机是坏的**：在训练用的朝向 `rotate=(90,180,0)` 下，画面里是**草地 + 机器人自己的右臂/肩膀**，
  完全没有前方的按钮面板。（现场预览截图已确认。）

三方证据一致：

| 证据 | 结果 |
|---|---|
| 现场预览截图 | 右腕相机对着草地/手臂，看不到面板 |
| 腕相机 rotate 三轴 64 个朝向全扫（含 roll）| 与 v6 训练腕相机画面的归一化互相关**最高仅 0.38**，无任何朝向能对上 |
| 闭环评测（黄色，从 ready 起点，起点位姿实测 8mm/3° 完美对齐训练首帧）| rotate=(90,180,0) 无标定：**195mm**；自动标定转到最好朝向：**125mm**——都失败 |

对照：v6 **训练数据**本身四色均衡且优质（红206/绿199/蓝201/黄194 集，各色到位 ~70mm、成功率 100%、按错 0%），
模型见过大量成功的黄/蓝示范。所以够不到只可能是**评测时右腕这路输入坏了**。

## 2. 原因

- 按钮任务的相机朝向由 `orcalab_camera_prep.sh` 统一设置：对 `/g1_omnipicker/camera_right`
  设 `rotate=(90,180,0)`。**两台机器跑的是同一条命令、同一 rotate 值。**
- 布局文件 `g1_button.json` 里 `camera_right` 只有推流属性（端口、裁剪面），**没有位姿/朝向覆盖**。
- `camera_right` 是刚性挂在机器人右臂末端连杆上的子实体，挂载链为：
  `... → arm_r_end_link → camera_right_body1 → camera_right_body2 → cameras → camera_right`。
  它相对手腕的**朝向烘焙在 `g1_omnipicker` 模型 pak 里**。
- 既然 rotate、ready 关节位姿、布局都一致，唯一能让同一 rotate 产生不同视角的，
  就是**这个烘焙在模型 pak（或 OrcaLab 版本）里的相机挂载朝向在两台机器上不一样**。
  这与既有观察"相机随导出/冷启动漂移"一致。

## 4. 判定与处理

- **若 4060ti 的 pak/版本与本机不同** → 把本机 `g1_omnipicker`/`camera` pak、OrcaLab 同步到采集机版本，
  重跑评测即可在本机复现正确视角。**这是最希望的情况。**
- **若完全相同却仍不同视角** → 说明是冷启动/导出的非确定性烘焙漂移，本机无法稳定复现采集视角，
  那就把**评测客户端放到 4060ti**（相机视角天然一致），策略服务留在 4090，两端用网络连接。
