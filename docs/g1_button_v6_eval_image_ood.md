# v6 闭环失败根因：评测时送进模型的腕相机图像分布外

本文记录 2026-09-11 在 4060 Ti（仿真 + 评测客户端）+ 4090（策略服务 `100.72.117.78:8010`，
`g1_button_local_v6/11999`）上做的一组对照实验。**每条结论都标注了是实测坐实还是尚未证实。**

结论一句话：**模型、语言接地、四色排序全都是对的；闭环失败完全由「评测时送进模型的腕相机图像
与训练帧对不上」造成。该策略对视角的容差只有 2~3 像素，而评测帧偏了 6~7 像素。**

---

## 1. 已坐实：模型本身没问题

在**训练录制帧**上、预备位姿第 0 帧、指令「按红色按钮」，取 `action[9]` 的右手位置：

| 输入 | 距训练真值 |
|---|---|
| 数据集第 0 集首帧 | **9.5 mm** |
| 换成第 2/6/8/13/16/23 集的首帧（6 张不同的合法训练图） | 9.2 ~ 19.0 mm |

换不同训练图像带来的预测散布：**最大两两距离 20.2 mm，平均 9.8 mm**；单帧重复采样的
σ 只有 3~12 mm。四色 y 排序 red > green > blue > yellow 与真值一致，两两间距是真值
（111~258 mm）的 80~85%。

→ **模型学到了，语言接地正常，采样噪声不是病因。** 这一条与 4090 那边 §2.1 的结论一致。

## 2. 已坐实：误差全部来自腕相机图像

同一个状态向量、同一条指令，只换图像来源：

| 图像来源 | 距真值 |
|---|---|
| 训练帧（基线） | **9.5 mm** |
| 评测帧（`--dump_dir` 存下、与实际发送逐字节同源） | **62.9 mm** |
| 评测头相机 + **训练腕相机** | **6.9 mm** ← 正确 |
| **训练头相机** + 评测腕相机 | **55.4 mm** ← 无改善 |

→ **头部相机的差异对预测毫无影响，全部误差来自腕相机。**

## 3. 已坐实：策略对视角的容差只有 2~3 像素

把**训练帧**人为平移若干像素（两路相机同时平移），看预测漂多少：

| 平移量 | 预测相对基线的漂移 |
|---|---|
| 2 px | **26 ~ 28 mm** |
| 4 px | **54 ~ 58 mm** |
| 8 px | 62 mm |
| 16 px | 44 ~ 77 mm |
| 评测帧（实测偏 6~7 px） | **80.7 mm** |

→ **4 个像素的视角偏移就能复现闭环里看到的全部误差量级。**

原因是 v6 的训练分布在首帧处**宽度为零**：800 集首帧右手位置标准差 **0.001 mm**、
姿态偏差 **0.000°**；头相机首帧跨集位移恒为 (0,0)、像素差只有 1.5~2.5 灰度级。
模型等于把同一张图看了 800 遍，没有任何视角冗余。

## 4. 已坐实：评测帧的偏移是确定性的、可复现的

| 比较 | 平均像素差 | 相位相关位移 |
|---|---|---|
| 训练 ep0 vs 训练 ep6（头） | 1.89 | (0, 0) |
| **评测第 1 次 vs 评测第 2 次（头）** | **2.03** | **(0, 0)** |
| 评测 vs 训练（头） | 13.6 | **(0, +5)** |
| 训练 ep0 vs 训练 ep6（腕） | 3.86 | (0, 0) |
| **评测第 1 次 vs 评测第 2 次（腕）** | **3.52** | **(0, 0)** |
| 评测 vs 训练（腕） | 17.4 | **(−6, +1)** |

两次独立评测（各自重启仿真、重新伺服）得到的图像，差异与训练集内部的自然差异同一水平。
**不是随机抖动，是一个固定的系统性偏移。**

## 5. 已坐实：不是 OrcaLab 会话/资产变了

今天（2026-09-11）在当前这个 OrcaLab 会话里，用**采集脚本**原样重采 1 集：

```
首帧右手 ee   v6 [0.5363 -0.3067 0.2871]   今天重采 [0.5363 -0.3067 0.2871]   差 0.05 mm
cam_head      今天重采 vs v6   差 2.34   位移 (0, 0)     ← 完全对齐
cam_wrist_r   今天重采 vs v6   差 8.36   位移 (−2, −2)   ← 基本对齐
```

→ **采集路径今天跑出来的画面和三个月前的 v6 逐像素对齐。渲染、资产、机器人站姿都没变。
差异出在评测脚本的初始化路径上。**

## 6. 已排除的原因（逐条实测证伪）

| 假设 | 检验方式 | 结果 |
|---|---|---|
| 视频压缩（训练过 AV1、评测是原始帧） | 把评测帧压成 JPEG q90/q70 再送 | 56~67 mm，**无改善** |
| 亮度/色彩偏移 | 逐通道均值差 +0.6 / +1.6 / +0.2 | 可忽略 |
| 纯像素平移 | 按测出的位移把评测帧反向平移 | 72.9 mm，**更差** |
| 状态向量不对 | 评测起点 vs 训练首帧 | 位置差 **1.36 mm**、姿态差 **0.06°** |
| 机器人物理沉降 | 训练集内 0→60 帧头相机上半幅位移 | 恒为 (0,0)，**不沉降** |
| `set_default_joint_values` 时机不同 | 按采集做法在 `update_scene()` 后补设 | 关节偏差逐位相同，**无改善** |
| `env.set_ctrl(manager.ctrl)`（采集不调） | 加 `--diag_skip_set_ctrl` 跳过 | 末端位姿逐位相同，**无改善** |
| 相机映射/端口不同 | `BUTTON_CAMERA_MAP` vs `omnipicker_camera_map()` | 传感器名与端口完全相同 |
| 手臂零空间构型不同 | `_log_arm_q` 对比标称关节角 | **该证据无效**，见下 |

**关于关节角的更正**：日志里「OSC 伺服后关节偏差最大 97°」这个数字**不能作为证据**。
诊断实验显示，在评测进程里把右臂瞬移到标称关节角 `r_arm_ready["joint_values"]`，
末端跑到 `[0.3757, −0.8653, 0.0667]`——与预备位差 0.6 米。即评测脚本里那句注释是对的：
「同一组关节角在不同进程对应不同物理姿态」。所以那 97° 是拿一个在本进程里已失效的参考
算出来的。**`drive_to_ready` 不是多余，是必需的。**

## 7. 尚未查清

**评测路径里究竟是哪一步让腕相机偏了 6~7 像素，还没定位到。** 已知：

- 它是确定性的、可复现的（§4）
- 它不是渲染/资产/会话差异（§5）
- 它不是上表中任何一条（§6）
- 末端位姿只差 1.36 mm，但头相机的**静止背景**也偏了 5 px——头相机不随手臂动，
  所以至少有一部分偏移与手臂无关

## 8. 这对下一步意味着什么

即使找到了第 7 节那个差异并修好，**「策略对 4 个像素的视角偏移就损失 55 mm」本身就是缺陷**。
比赛现场任何一点视角差异都会重演。所以修法必须落在训练侧：

1. **训练时加图像增强**（随机平移/裁剪 ±8 px、轻微旋转与亮度抖动）。
   不需要重采数据，直接在现有 800 集上重训。**这是成本最低、收益最确定的一步。**
2. **采集时加起始位姿扰动**：v6 首帧位置标准差 0.001 mm 是病根。下一版采集应让预备位姿
   在 ±5 mm / ±2° 范围内随机，让模型见过视角冗余。
3. 同时把 §7 继续查下去，让评测侧尽量对齐——但不要指望它单独解决问题。

## 9. 对 4090 侧 `g1_button_v6_closedloop_diagnosis.md` 的评估

| 该文结论 | 我这边的判断 |
|---|---|
| §2.1 模型学到了、四色接地正常 | **正确，独立复现**（本文 §1） |
| §2.2 近按钮「信噪比崩塌」 | **测量本身没问题，但解释不了闭环。** 那张表里的「预测误差 ~5 mm」是喂**训练帧**测出来的；评测时喂真实帧误差是 **60~80 mm**，差 12~16 倍。按该表，在 143 mm 处示范位移 5.4 mm/帧、模型误差 5.0 mm，应当缓慢前进而不是停成不动点。**「果断收尾」是治标。** |
| §3 蓝/黄「下排按钮运动学更难」（该文已标注未证实） | **可能不需要这个机制。** 评测帧造成的是一个**方向一致的系统偏置：x +30 mm、y +65 mm**。四色 y 真值 red −0.270 > green −0.295 > blue −0.329 > yellow −0.358，+65 mm 的 y 偏置把每一色的预测都推向 red/green 那一侧——正是蓝/黄出现「非最近按钮」的方向。一个机制同时解释了停滞和错按钮。 |
| §5 诚实标注「已坐实 / 待证实」 | **做法正确**，该文对自己前后两次归因的自我修正也站得住 |

**两边都漏做的那个实验**：所有离线探针（双方的）喂的都是**训练录制帧**。
把 `--dump_dir` 存下的**评测实际发送帧**喂进去，才暴露出问题。建议 4090 侧复现本文 §2 的
A/B 对照。

## 10. 复现本文实验的脚本

诊断脚本在 `scripts/openpi/` 下（`offline_eval.py` 的第 0 帧语言接地测试），
本文用到的一次性对照脚本未入库，逻辑都写在上面各节里，核心是：

```python
# 固定状态向量与指令，只换图像来源，比较 action[9] 的右手位置
cli.infer({"state": st, "images": imgs, "prompt": "按红色按钮"})["actions"][9, 7:10]
```

评测脚本新增的诊断开关（默认行为不变）：

| 开关 | 作用 |
|---|---|
| `--diag_teleport_dump` | 抓完首帧后瞬移回标称关节角再抓一张（会破坏本集，仅诊断用） |
| `--diag_skip_set_ctrl` | 跳过 `env.set_ctrl(manager.ctrl)`，与采集脚本一致 |
| `--no_default_joints` | 不在 `update_scene()` 之后重设默认关节角（旧行为，仅对照用） |
| `--ready_mode {servo,hold}` | `hold` 会钉住瞬移后的位形；**实测不可用**（位置伺服组已禁用，手臂会掉） |

另外每集会打印 `[关节] ... 偏差(度) ...` 一行；如第 6 节所述，该数值在跨进程比较时无意义，
仅用于观察同一进程内 OSC 前后的变化。
