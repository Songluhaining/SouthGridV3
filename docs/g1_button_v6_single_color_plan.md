## 0. 先读这段：评测怎么执行，决定了数据怎么采

我们**不再让策略自己走完多按钮序列**。评测时的执行流程是：

```
官方指令「先按绿色按钮，再按红色按钮，再按黄色按钮，最后按蓝色按钮」
        │
        ├─ 脚本解析 ──▶ 颜色列表 [绿, 红, 黄, 蓝]
        │
        ▼
   ┌──────────────────────────────────────────────┐
   │ 取列表下一个颜色 c                             │
   │ 给策略下发单色指令「按c色按钮」                  │
   │ 策略：从预备位姿出发 ──▶ 把这一个按钮按下        │  循环 4 次
   │ 脚本：检测到按下 ──▶ 伺服把手臂送回预备位姿       │
   └──────────────────────────────────────────────┘
```

**所以策略只需要会做一件事：从预备位姿出发，按下语言指定的那一个按钮。**
它永远不需要判断"我进行到第几个了"，也永远不会从一个陌生的位姿开始——
因为每按完一个都会被送回同一个起点。

**v6 数据就是严格照着这一件事采的**：每一集都是「预备位姿 → 按一个按钮」，
一集一个按钮、一次按压、一句规范指令，**没有任何多按钮组合**。

### 为什么必须这样，而不是让策略自己走序列

pi0.5 **每一步只看当前一帧画面，没有任何历史记忆**（训练时图像张量是
`(B, 224, 224, 3)`，没有时间维度）。让它自己走完四按钮序列时会发生：

- 按钮按完会**弹回原状**，画面上看不出哪些已经按过；
- 同样的画面 + 同样的完整指令，可能该去绿色也可能该去红色，取决于进行到第几步；
- 这种帧对语言通道来说不是"冗余"，而是**无解**——等价于标签噪声。

v4 里这类帧占了 **62%**，梯度下降的结果就是把语言整个丢掉：实测**单色接地正确率 25%**
（等于四选一瞎猜），换四种颜色指令预测目标**只差 9 毫米**（作为对照，四个按钮实际相距十几厘米）。

换成"脚本调度 + 每次回位"之后：

| | 效果 |
|---|---|
| 每段起点都是同一个预备位姿 | **训练分布与评测分布完全重合**，不存在分布外状态 |
| 每一帧的颜色词都充分且必要 | 语言不可能被忽略，"捷径解"从根上不存在 |
| 回位耗掉的时间 | 正好满足官方 P2 反速通规则（见 §2），于是按压本身可以采得很快 |
| 失败可隔离 | 回位是脚本、成功率 100%；策略只做数据覆盖最充分的那一个动作 |

### 这样做合规吗

合规。指南第 1.1 节明确允许「使用自己独立编写的控制算法、规划器或策略网络替代官方脚本，
只要最终能向 `ScorerClient` 提交符合评分规则的动作结果」；第 4.2 节的技术路线表里
「直接关节控制 + HEFT 站立」的优点写的就是"已有满分参考实现"。
评分全程仍由官方 `ScorerClient` 判定，传给 `start_attempt` 的 `targets`
与下发完整指令时**完全相同**——改变的只是"该按哪个"这个调度放在模型里还是脚本里。

**唯一红线**：禁止「非实时控制」。回位必须是**真实伺服**
（`drive_to_ready`：位置线性插值 + 姿态 slerp），**绝不能瞬移**。
注意采集脚本每集起点用的是瞬移（`READY_STEPS` 注释里写明），那是采集时的做法且不录制，
**评测时照搬会踩线**。

## 1. 这版数据与 v4 / v5 的区别

| | v4 | v5 | **v6（当前）** |
|---|---|---|---|
| 组成 | 1/2/3/4 键混合，**四键占 62% 帧** | 补单色后四键降到 28% | **100% 单色单次按压** |
| 指令 | 505 种说法，中位每种 1 条 | 同上 + 补采的规范句 | **只有 4 句规范句** |
| 时钟门控 | `--clock wall`（墙钟） | 同 v4 | **`--clock sim`（仿真时间）** |
| 帧间隔 | 4.46~8.90 控制步，**随机器忙闲浮动** | 同上 | **恒定 10 控制步** |
| 采集节奏 | 9.5 秒/钮 | 同上 | **4.2 秒/钮** |
| 规模 | 1000 集 / 997k 帧 / 5.7 GB | 972 集 / 694k 帧 | **800 集 / 61.6k 帧 / 496 MB** |
| 采集速度 | 25 秒/集（单色） | 同上 | **9 秒/集** |

三个改动分别解决三件事：

**① 只采单色** —— 与上面的执行方式一一对应。策略只需要学"从预备位姿按一个指定颜色的按钮"，
多按钮的帧对它不但没用，还会教它忽略语言。

**② `--canonical_ratio 1.0`，指令只留 4 句规范句**

```
按红色按钮    按绿色按钮    按黄色按钮    按蓝色按钮
```

评测脚本用 `--auto_segment` 生成的**就是这四句**（`f"按{颜色}按钮"`），
与训练标注**逐字节一致**，不存在任何漂移空间。v4 的 505 种说法、中位每种只有 1 条样本，
是语言学不好的另一个原因。

**③ `--clock sim`，帧间隔恒定**

v4 用墙钟门控，每个记录帧跨多少控制步取决于采集机器当时的快慢，实测在 4.46~8.90 之间浮动——
**同样的画面对应差两倍的动作位移**，模型只能学一个平均值。改用仿真时间门控后：

```
帧间隔 min 0.0500s   max 0.0500s   唯一值数 = 1   →   每帧恰好 10.00 控制步
```

副产品是**评测的 `--action_repeat` 有了确定值 10**，不用再靠试。

### 与 v4 刻意保持一致的部分

`--success_mode official`（**不要传 `press`**，那会把瞄准点往里推 4 厘米，
而官方得分曲线顶点在 5 厘米处，压深反而扣分）、`--fps 20`、同一布局 `g1_button.json`、
同一初始位姿、同一份轨迹候选 yaml、同一条驱动脚本 `auto_collect_windows.py`。

## 2. 官方评分口径：P2 反速通规则

评分实现在
`src/examples/dataCollection/g1_omnipicker/g1_omnipicker_collection_scripted_button_combo_lerobot.py:247-258`：

```
OFFICIAL_STEP_SCORE  = 10.0   每个按钮满分 10 分（任务满分 40）
OFFICIAL_PEAK_M      = 0.05   末端到按钮 site 距离 0.05m 得满分，0m 与 0.10m 都只有 6 分
OFFICIAL_P1_DISCOUNT = 0.35   最佳帧上最近的不是目标按钮 → 该步 ×0.35
OFFICIAL_P2_SPAN_S   = 20.0   四钮最佳帧跨度 ≤ 20s → 全部 ×0.6
OFFICIAL_P2_FAST_S   = 5.0    跨度 ≤ 5s → 全部 ×0.4
```

**P2 解释了 v4 为什么采得那么慢**：作者按它倒推出 9.5 秒/钮（四钮跨度须 > 20 秒，即每钮 > 6.7 秒）。
标定实测把节奏压到 4.2 秒/钮时，**每次按压质量完全不变**（official 9.05~9.44、site 距 68~74mm），
但四钮跨度触发 ×0.6、整集判废。

**关键例外：P2 只在"一次尝试凑满 4 个按钮"时触发**（`len(best_times_s) < 4` 直接返回 1.0）。
**所以单色集怎么快都不受限**——这就是 v6 能又快又不丢分的原因；
而评测时缺的那点时间，由回位段自然补上。

数据能达到的上限：每次按压 official 约 9.3 分，四钮合计约 **37/40**。

## 4. 训练

```bash
ln -sfn <v6目录> $HF_LEROBOT_HOME/local/g1_omnipicker_button_combo

cd openpi     # 已按 openpi_patches/g1_button/README 打过补丁
uv run scripts/compute_norm_stats.py --config-name pi05_g1_button_lora

uv run scripts/train.py pi05_g1_button_lora --exp-name g1_button_v6 --overwrite \
    --num-train-steps 12000 --lr-schedule.decay-steps 12000 \
    --batch-size <显存能放下的值，24GB 卡建议 16>
```

三个要点：

- **换了数据集必须重算归一化统计**，否则动作幅度会错。
- **步数从 30000 降到 12000**：61.6k 帧跑 30000 步是 10 个轮次，容易过拟合。
  `--lr-schedule.decay-steps` **必须同步改**，只改步数会让学习率停在半路降不到位。
- **不要与 v4 / v5 混训**：那两批是墙钟门控 + 慢节奏，混进来会把 v6 刚消除的时序抖动重新引入。

## 5. 评测

评测脚本新增三个参数（本分支已改）：

| 参数 | 默认 | 作用 |
|---|---|---|
| `--auto_segment` | 关 | 把 `--prompt` 里的官方指令解析成颜色列表，逐个下发与训练逐字一致的 `按X按钮` |
| `--return_move_steps` | 600 | 段间回预备位姿的插值步数 |
| `--return_settle_steps` | 200 | 回位后钉住目标等 OSC 收敛的步数 |

段间回位本身是脚本原有功能（`--start_pose ready` 默认开启），
但原来复用的是每集起点那 150+150 步、只有 1.5 秒，会让四钮跨度掉到 17.1 秒触发 P2，
所以拆出独立参数。

```bash
python eval_g1_omnipicker_button_lerobot.py \
    --task_config ../../dataCollection/common/example.yaml \
    --host <策略服务器> --port 8010 \
    --prompt "<官方给的完整指令>" \
    --auto_segment --action_repeat 10 --max_steps 3000
```

日志会打印
`[auto_segment] 「先按绿色按钮，再按红色…」-> 按绿色按钮 | 按红色按钮 | 按黄色按钮 | 按蓝色按钮`，
可直接核对下发给策略的文本是否与训练一致。

### 配速核算（按 v6 实测）

| 环节 | 仿真时长 |
|---|---|
| 一次按压（74 帧 × 10 控制步 × 5ms） | 3.70 s |
| 回位（600 + 200 步） | 4.00 s |
| 单次循环 | 7.70 s |
| **四钮最佳帧跨度 = 3 × 7.70** | **23.1 s** > 20 s ✅ 余量 15% |

跨度不够就加大 `--return_move_steps`。`--action_repeat` 也可调
（10 是原速，调小提速、调大放慢），但调小会同时压缩跨度，两者要一起算。

### 三个不要

- 不要传 `--success_mode press`（几何偏 4 厘米，且压深扣分）
- 不要用 `--action_repeat 1`（官方指南示例里的值，会让机器人快 10 倍、够不到按钮）
- 不要手工传 `--prompts` 拼指令（容易多打一个字就落到样本稀疏的说法上，用 `--auto_segment`）

## 6. 训练完先做离线验证，再开仿真器

```bash
python scripts/dataset/lang_grounding_probe.py --ckpt <新checkpoint> --dataset <v6目录> --per_color 6
```

**单色接地正确率 ≥ 85%** 才上仿真器。也可以用 `scripts/openpi/offline_eval.py`，
它额外给出"四色指令预测目标最大差"——按钮相距十几厘米，**应为上百毫米**；
小于 10 mm 说明仍在忽略语言，那就不必去跑仿真器评测了，先查原因。
