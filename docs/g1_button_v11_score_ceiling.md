# 按钮任务的分数天花板：接触把官方距离钉死在 70mm

2026-09-13。起因是「还差 6.58 分，剩下哪些没得分」的拆解，结论被一次 20 集试采推翻，
连带查出一个会静默采废数据的标定隐患。本文只记录**实测**，推断部分都标注了。

---

## 1. 官方得分曲线（`site-packages/configs/tasks.yaml:113-138` 实读）

```
success: site_distance(${robot.ee_site_right}, ${target_button_site})
score_curve: parabola  [0,0.60] [0.05,1.00] [0.10,0.60] [0.30,0.00]
noise: amplitude 0.03, seed 42, only_above 0.05
```

- `ee_site_right` 在 `configs/robots.yaml:26` 解析为 `g1_omnipicker_ee_center_site_r`，
  与采集脚本自检、评测脚本用的是**同一个 site**，评分链路上**没有任何偏置修正**
  （`scorer_service/engine.py:1251` 那处只统计路径长度与最大速度，不参与计分）。
- 顶点在 **50mm**，而 **d=0 只有 6 分**——这条曲线的设计意图是
  「靠近但不要撞上去」，撞上去是要扣分的。
- 曲线拟合为 `ratio(d) = 1 - 160*(d-0.05)^2`（d ≤ 0.10），与实测吻合：
  70.6mm→9.32、80mm→8.56、90mm→7.44。

## 2. 被推翻的假设：「把采集瞄准点改深就能提分」

v6 采集用 `--target_site_dist 0.047`（脚本注释写明意图是让距离落在 50mm 顶点附近），
实测 800 集落在 **70.6mm ± 1.2**。据此曾推断「差 23.6mm 是跟踪误差，补偿掉能多拿 5.6 分」。

**20 集试采直接证伪**：下达 21mm（比 v6 深 26mm），实际落在 **70.3mm**，只变了 0.3mm。

对比两批数据看出机制：

| 色 | v6 下达47mm：site/压入/几何-帽 | 试采 下达21mm：site/压入/几何-帽 |
|---|---|---|
| red | 70.1 / 3.20 / 26.0 | 70.3 / **9.78** / 25.8 |
| green | 70.5 / 8.25 / 26.9 | 69.7 / **9.20** / 26.0 |
| blue | 69.7 / 6.98 / 32.3 | 69.5 / **9.57** / 31.3 |
| yellow | 72.5 / 14.75 / 30.8 | 71.8 / **17.52** / 29.4 |

按钮平均被多压进 6.6mm，「几何-帽」几乎不变（夹爪和帽子贴着一起走），
**官方距离一毫米没变**——因为**按钮 site 是跟着帽子滑的**：手往里推多少，目标就往里退多少。

**结论：一旦接触，官方距离被钉死，瞄得再深完全无效。**
采集脚本里原本就有这句注释（「压入既不加分，按钮 site 随帽滑动，距离不变」），
但没人推到它的推论上。

### 夹爪几何（`src/model/G1_omnipicker/g1_omnipicker.xml:269`）

```
ee_center_site_r   在腕部末端 z = +0.080
两指根部            z = +0.0565 / +0.0739，分居 x = ±0.0195（间距 39mm）
指节链再往前        0.031 + 0.018 + 指尖 ≈ 再伸 45mm
```

闭合时指尖比 site 前伸约 45mm。指尖顶住帽子时 site 还在 70mm 外——
**70mm 是闭合夹爪正面接近的几何硬极限，够不到 50mm 的顶点。**
闭合夹爪的示范上限因此是 9.33 分/钮 = **37.3 分**，不是 40 分。

## 3. 模型侧：从来没碰到过按钮

评测日志（`G:/datasets/eval12/dwell_c.log`）：

```
红色 压0.0mm 距49mm 官方83mm | 绿色 压0.0mm 距45mm 官方79mm | 蓝色 压0.0mm 距43mm 官方80mm
```

示范是「夹爪离帽 26~32mm、按钮压进 3~17mm」，模型是「离帽 43~49mm、压入 0.0mm」——
**模型差的是最后约 17mm 的接触**，官方距离因此差 9~13mm。

### 为什么停早了：训练数据里三分之一的帧在教「别再往前」

对 v6 前 60 集逐帧统计（每集 77.5 帧）：

```
到达最深点        第 57.7 帧（74.5%）
最深点之后        19.8 帧（25.5%）—— 保持 + 后撤
接触后推不动的帧   7.5 帧
```

而**评测里段间是脚本回位**（`eval_g1_omnipicker_button_lerobot.py:530,1259` 的
`drive_to_ready`），不是模型控制——**那 19.8 帧/集的后撤数据在评测中一次都用不到**，
只是在把终点吸引子往外拉。这是「模型提前 17mm 停住」的一个可检验的解释（尚未做消融）。

## 4. 顺带查出并修复的标定隐患

采集脚本原本用「候选位姿的 y-z 最近邻」把颜色映射到按钮，**没有一一对应约束**。
帽心是在**基座坐标系**里算的，标定又发生在 episode 循环之外（瞬移回标称位姿之前），
所以只要底盘不在标称位姿，整个电柜在基座系里平移，映射就会错——**而且不报错**。

实测复现：一个残留的评测进程把底盘留在偏 66mm 处，于是

```
蓝色候选 y=-0.2451 → 到 button02 距 51.9mm，到 Button03 距 67.1mm  ⇒ 命中 button02
```

**蓝色和绿色一起瞄了 button02**，20 集数据里蓝色全是废的，质量闸门一条都没拦住。

已改为按官方 `configs/tasks.yaml` 的名字硬映射（`red→button01 … yellow→button04`），
几何最近邻降级为交叉校验并在不一致时告警，另加一一对应自检（撞车则当场退出）。

已核对：**v6 那 800 集的映射全部正确**（red→button01 / green→button02 /
blue→Button03 / yellow→Button04，无一例外），v9 的训练数据没有被污染；
评测脚本本来就是按名字硬映射的（`:192`），历次本地测距也没受影响。

## 5. 张开夹爪：绕过指尖，但撞上手臂可达边界

张开后两指分居帽子两侧，帽子从中间穿过，挡在前面的变成掌面（z≈0.075，与 site 几乎齐平）。
两轮各 8 集探针（`--grip_r_approach -0.8561`）：

| 色 | 瞄 50mm | 瞄 30mm | 压入(30mm) |
|---|---|---|---|
| red | 70.5 | 72.8 | 5.77 |
| green | 71.2 | 67.3 | 2.89 |
| blue | **62.9** | **59.8** | 0.00 |
| yellow | 63.1 | **62.2** | 0.00 |

看蓝色：手指离帽子还有 45.9mm、压入 0.00，**全程没碰到任何东西，可它还是停在 59.8mm**。
而瞄准点从 50mm 改到 30mm（深 20mm），实际只前进了 3.1mm。

**限制因素变成了手臂的运动学可达边界。** 采集脚本自己的警告说得很直白：
「帽心 x=0.8479，超过约 0.87 即接近可达边界」。ee_site 的极限 x 约 0.788，
帽心在 0.848，差 60mm——正好是蓝色停住的地方。

red/green 停在 67~73mm 是因为张开的手指又碰到了东西（压入 2.9~5.8mm），需要逐色调开合度。

### 三层天花板

```
得分曲线顶点            50mm   → 10.00/钮 → 40.0    够不到
手臂运动学可达极限      ~60mm  → 9.84/钮  → 39.4    张开夹爪的上限，需逐色调参
闭合夹爪指尖接触        ~70mm  → 9.33/钮  → 37.3    v6/v9 的上限
模型实际停住            ~82mm  → 8.36/钮  → 33.4    现在
```

### 为什么先不走张开夹爪这条路

闭合夹爪那堵「接触墙」其实是优势：撞上去就钉在 70mm，多推无害，
**模型只要「一直往前推到推不动」就能拿 9.33 分，不需要精确**。
张开夹爪没有墙，模型必须精确停在 60mm，而它现在有 12~17mm 的误差，反而会掉分：

| 路线 | 示范上限 | 模型带 12mm 欠冲 | 成本 |
|---|---|---|---|
| 现状（闭合，v9） | 37.3 | 33.4 | — |
| 让模型真正推到接触（闭合，不重采） | 37.3 | ≈36~37 | 数据裁剪 + 续训 ~2.6h |
| 重采成张开夹爪 | 39.4 | ≈35.5 | 重采 + 重训，且需逐色调开合度 |

**先做第二行**：更便宜、收益更大、不用重采。张开夹爪要等模型能精确跟踪之后才划算。

## 5b. 模型为什么停早了：它在提前后撤

开环探测（12 集，v9，同一帧观测直接问下一步走多少；`scratchpad/terminal_probe.py`）：

```
相对最深帧   剩余前进量   真值前进   模型预测   预测/真值
   -14       30.1mm    22.7mm   13.1mm    0.58
   -10       20.6mm    20.6mm    3.9mm    0.19
    -7       14.0mm    12.3mm    7.4mm    0.60
    -5        9.6mm     3.8mm   -4.7mm   ← 真值还在前进，模型已经在后退
    -3        5.1mm    -7.5mm   -7.9mm   ← 匹配（数据本身已进入后撤）
    -1        0.9mm   -20.2mm  -20.5mm   ← 匹配
```

模型把**后撤学得很准**，却在还差 9.6mm 时就开始往回走——这个 9.6mm 与闭环实测的
9~13mm 官方距离欠冲吻合。它分不清「靠近按钮」和「该收手了」。

而评测里段间是脚本回位，**模型永远不需要自己后撤**。

## 5c. 对策：把最深帧之后的帧裁掉

`scripts/openpi/truncate_after_deepest.py`：每集裁到 `argmax(state[:, 7])`（右手 x 最大）为止，
只改 parquet 行数与 meta 计数，视频原样复用（解码按时间戳取帧，多余尾帧不会被读到）。

```
800 集：61621 帧 → 47630 帧（保留 77.3%）
抽查 40 集，末帧全部即最深帧；LeRobotDataset 加载正常
```

训练侧（A800，配置 `pi05_g1_button_lora_v11`）：

- 数据集换成 `g1_button_v6t`，其余与 v9 逐字相同（增强 0.88/7°/0.12）
- 权重从 `/root/keep/v9_step7999/params` 续训，3000 步，peak_lr 2e-5，warmup 200
- **归一化统计直接复制 v9 的**（md5 一致），不在 v6t 上重算——重算会改变输入输出归一化，
  v9 的权重就不再是同一个函数，续训等于从被扭曲的起点开始

## 6. 复现用的命令

```bash
# 探针：<输出目录名> <target_site_dist> <grip_r_approach|none> <集数>
bash probe.sh g1_button_probe_o30 0.030 -0.8561 8
```

仿真跑几轮后会退化（表现为「录制首帧偏离 ready 304mm，本集判废」+
「连续按压失败，请重启仿真」），**每次探针前必须重启仿真**。
